# NovaSVN 设计文档

## 产品定位

NovaSVN 是面向 Windows 和 macOS 的桌面 SVN 客户端。界面和主要工作流以 Versions 为基线，优先提供清晰、紧凑、符合桌面应用习惯的工作副本、时间线和仓库浏览体验。

产品必须直接执行真实 SVN 操作，不能用演示数据或仅更新前端状态来代替命令执行。

## 设计原则

1. SVN 原生语义优先，不把 SVN 包装成 Git。
2. 不实现 Git 式暂存区。文件勾选只表示当前一次提交的目标，不持久化、不修改 `.svn` 元数据。
3. 常用操作出现在工具栏、文件行或检查器中，高级参数放在按需展开的区域。
4. 工作副本和仓库数据使用高密度表格，不使用大卡片堆叠信息。
5. 后端统一封装 SVN 命令、路径校验、错误和任务状态。
6. 每个小功能独立验证并单独提交 Git。

## 信息架构

### 工作副本

工作副本是默认视图，结构对齐 Versions Working Copy View：

- 顶部工具栏提供刷新、Update、Commit、Revert、Cleanup 等常用操作。
- 主表显示文件树、状态、Base revision、Last revision、日期和作者。
- 文件行按状态显示 Commit、Update、Add、Resolve 等行内操作。
- 文件表使用复选框和 Shift 范围选择支持多选；批量 Revert、Move、Delete 必须在单个后端任务中整体校验后执行。
- 文件表作为 treegrid 提供单一键盘入口；方向键移动活动行和树层级，Enter 激活，Space 选择，Shift 扩展范围，Ctrl/Cmd+A 选择可见路径。
- 单击文件名称只选择检查器目标，双击才通过系统默认应用打开；缺失目标、目录和解析后逃逸工作副本的符号链接不得进入文件打开命令。
- 右击未选路径切换单项选择，右击已选路径保留多选；菜单按状态显示单项或批量操作，并提供 Menu 键、Shift+F10、方向键和 Escape 语义。
- 应用原生工作副本菜单包含当前活动路径子菜单，复用相同的状态判断与真实操作入口；工作副本、任务或活动行变化时同步更新菜单文本和禁用状态。
- 本地状态来自 `wc-status`，远端更新来自 `repos-status`；同一路径两者都有变化时必须明确显示组合状态。
- 可切换全部文件、本地改动、远端更新和未版本控制文件；远端检查不可用时不能显示为零更新。
- 右侧检查器通过 Information、Properties、Diff、Blame、Commit 和 Tasks 标签显示信息、属性、锁状态、差异、逐行历史、提交表单和任务反馈。
- 提交目标默认选择全部可提交的版本控制改动，用户可在本次提交前取消选择。

提交目标选择只存在于当前会话。切换工作副本或任务工作区时必须清空，工作副本草稿只保存提交信息、审查状态和部分提交所需信息。

### 时间线

时间线对齐 Versions Timeline：

- Revision 按本地日历日期分组，组内保持仓库返回顺序，日期无效的旧数据进入独立未知日期组。
- 每项显示 revision、作者、时间、提交信息和改变路径。
- 改变路径可直接打开 revision diff。
- 支持作者、关键字、日期、文件范围和数量过滤。
- 支持连续分页加载，不重复 revision。

### 仓库浏览

仓库视图对齐 Versions Repository View：

- 使用目录树浏览任意仓库 URL 和历史 revision。
- 显示名称、Last revision、日期、作者和条目类型。
- 文件可打开临时副本、查看属性和日志。
- 目录支持 Checkout、Export、Import、Copy、Move、Delete 和创建目录。
- 分支和标签通过仓库 URL Copy 创建。

## 核心操作

| 操作 | 后端命令 | 交互要求 |
| --- | --- | --- |
| Update | `svn update` | 工具栏更新整个工作副本，远端变化文件行只更新对应安全相对路径，完成后刷新 |
| Revert | `svn revert` | 文件或多选入口、执行前显示完整影响范围并确认 |
| Cleanup | `svn cleanup` | 工具栏入口、显示真实命令结果 |
| Commit | `svn commit` | 提交目标勾选、提交信息、安全检查 |
| Add | `svn add` | 未版本控制文件行内入口 |
| Delete | `svn delete` | 文件行或多选入口、批量目标整体复检、执行前确认 |
| Move/Copy | `svn move/copy` | 工作副本和仓库各自使用对应命令；多选 Move 保留各源名称并移动到目标目录 |
| Merge | `svn merge` | 支持预检、revision 范围和 dry-run |
| Patch | `svn patch` | 选择文件、预检、应用和结果列表 |
| Log | `svn log --xml` | 时间线、文件历史、分页和过滤 |
| Blame | `svn blame --xml` | 逐行显示 revision、作者、日期和内容 |
| Lock/Unlock | `svn lock/unlock` | 检查器和文件行入口 |
| Resolve | `svn resolve` | 冲突文件显示明确解决策略 |
| Properties | `svn proplist/propset/propdel` | 属性检查器读写 |

所有可能访问远端仓库的命令都需要统一的认证、证书、非交互和超时策略。任务取消必须能够终止运行中的子进程，而不是只改变前端状态。

外部 Patch 必须位于目标工作副本之外，文件目标只能使用工作副本内的安全相对路径，且不能指向 `.svn` 管理目录或经符号链接逃逸。首次 dry-run 返回 Patch 的 SHA-256 摘要，真实任务必须匹配该摘要，并对同一份不可变快照再次 dry-run。即使 SVN 返回退出码 0，也要解析 rejected、skipped 和冲突输出，存在任一问题时禁止真实应用。

## 提交模型

文件级提交直接使用用户本次勾选的 SVN 路径：

1. 状态扫描完成后默认选择可提交的版本控制改动。
2. `unversioned` 必须先执行 Add，不能直接进入 Commit。
3. `missing`、`conflicted`、`obstructed` 和 external 不能直接成为提交目标。
4. 用户取消选择只影响当前提交，不写入本地存储。
5. 提交成功后清空本次选择并重新扫描状态。

文本 Hunk 级部分提交是独立高级能力。它使用影子工作副本生成和应用选中 Patch，不改变真实工作副本内容；成功后必须明确同步真实工作副本。

## 后端架构

Rust 后端按职责拆分：

- `workspace.rs`：工作副本信息、状态、文件树、Diff、Log、Blame 和属性。
- `task.rs`：有副作用或耗时操作的任务队列和 SVN 命令执行。
- `diff.rs`：Unified Diff 解析和选中 Hunk Patch 生成。
- `branch_pool.rs`：分支工作副本池。
- `shadow.rs`：部分提交影子工作副本。
- `external_tool.rs`：外部 Diff/Merge 工具和系统文件操作。
- `system_integration.rs`：Finder、Explorer 和启动意图。
- `error.rs`：稳定错误码和统一响应结构。

前端只能通过 `src/lib/api.ts` 调用 Tauri command。组件不直接拼接 SVN 命令，也不自行判断本地路径安全性。

## 状态与持久化

允许持久化：

- 最近工作副本。
- SVN 可执行文件和外部工具设置。
- 提交信息草稿和模板。
- 文件审查状态。
- Hunk 选择和影子工作副本元数据。
- 分支池和任务工作区元数据。

禁止持久化：

- 本次文件级提交目标。
- 运行中命令的伪完成状态。
- 可以由 SVN 状态重新计算的文件状态。

## 视觉基线

- 工具栏高度约 44px，优先使用图标按钮和工具提示。
- 文件表格行高约 27-30px，选中状态明确且不改变布局尺寸。
- 侧栏、主表和检查器使用连续分栏，不把页面区域包装成浮动卡片。
- 浅色和深色外观都通过语义颜色变量实现。
- 最小窗口尺寸必须与 CSS 布局一致，不能出现不可访问的横向裁切。
- 所有按钮、菜单、表格和分隔条支持键盘操作和可见焦点。

## 验证要求

每项功能至少提供以下证据中的两类：

- Rust 单元测试或真实临时 SVN 仓库测试。
- Store 或组件测试。
- TypeScript 和生产构建通过。
- 本地桌面窗口或浏览器截图验证布局。
- 命令日志证明真实 SVN 操作成功。

完整发布前必须覆盖 Windows 和 macOS 的安装包、系统集成、认证、证书和真实远端仓库流程。
