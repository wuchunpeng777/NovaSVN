# NovaSVN 升级策略

## 当前策略

开发预览阶段使用手动签名安装包升级，不在应用内静默下载或执行更新。原因是自动更新必须同时具备稳定下载域名、独立 updater 签名密钥、Windows/macOS 正式代码签名和可回滚发布服务；在这些条件缺失时接入自动更新会降低供应链安全性。

每个发布版本必须：

1. 使用 `npm run version:sync -- --set <version>` 同步 package、lockfile、Rust、Tauri 和 Finder Sync 版本。
2. 通过 `npm run version:check`。
3. 分别生成经过平台签名和平台验收的 NSIS/DMG。
4. 运行 `npm run release:manifest` 生成 `release-manifest.json`。
5. 运行 `npm run release:manifest:verify` 重新计算字节数和 SHA-256，拒绝发布后被修改的文件。
6. 上传安装包、清单、更新日志和平台签名/公证证据。

macOS 发布验收会自动生成并复验清单。Windows 实机发布流程接入清单前，正式发布仍保持阻塞。

## 产物清单

清单包含固定 schema、产品、版本、升级策略，以及每个安装器的平台、类型、架构、相对路径、字节数和 SHA-256。生成器只接受：

- `bundle/dmg/*.dmg`
- `bundle/nsis/*-setup.exe`

清单拒绝符号链接、发布目录外路径、重复平台/类型/架构和与 `package.json` 不一致的文件名版本。SHA-256 用于传输完整性；真实性仍由 Authenticode、Developer ID 和 notarization 保证，不能用 checksum 代替代码签名。

## 版本与兼容

- 正式版本遵循 SemVer，发布版本必须单调递增。
- 同一版本号的安装包发布后不可替换；修复必须提升 patch 版本。
- 工作区草稿、任务历史和设置需要保持向前兼容；新增持久化字段必须提供默认值。
- 新版本首次启动失败时，用户通过上一版本签名安装包回滚；回滚不得自动删除工作副本、草稿或应用数据。
- 涉及不可逆数据迁移时，必须先提供备份、迁移版本标记和单独回滚方案。

## 自动更新启用条件

满足以下条件后才能接入 Tauri updater：

- Windows Authenticode 和 macOS Developer ID/notarization 已各完成至少一次真实发布。
- 生成独立 updater 私钥并离线保存，应用只内置公钥。
- 使用 HTTPS 更新 endpoint，服务端发布不可变版本元数据和 updater signature。
- CI 能在隔离环境完成安装、升级、重启、版本确认和回滚演练。
- 支持分阶段发布、暂停渠道和撤回有问题版本，不把降级包伪装成更高版本。

在这些条件完成前，应用不引入占位公钥、示例 endpoint 或绕过签名的开发更新通道。
