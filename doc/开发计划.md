# NovaSVN 开发计划

## 开发原则

NovaSVN 的开发目标是逐步交付一个现代化、高性能、跨平台的完整 SVN 客户端。开发顺序必须先打通稳定闭环，再扩展高级能力。

基本原则：

- 先保证工作副本打开、状态扫描、diff、暂存、提交这些核心路径稳定。
- 所有 SVN 操作先通过 `svn` 命令行实现，并统一封装在后端接口中。
- UI 从第一版开始按完整工作台设计，避免后续大改布局。
- 大型工作副本性能从第一版就纳入设计，不等后期补救。
- 虚拟暂存区是核心交互模型，不能依赖临时改写真实工作副本。
- 部分提交必须通过影子工作副本保护用户真实文件。
- Windows 和 macOS 都作为目标平台，但系统右键菜单放到后期实现。

## 阶段 0：工程脚手架和基础架构

目标：建立可持续开发的 Tauri + Svelte + TypeScript + Rust 工程，并定义前后端通信、错误模型、任务模型和基础 UI 框架。

### 0.1 初始化工程

功能：

- 创建 Tauri 应用。
- 配置 Svelte + TypeScript。
- 配置 Rust 后端模块结构。
- 配置基础开发脚本。
- 配置应用名称、窗口尺寸、图标占位。
- 建立 `src-tauri` 和前端目录的约定结构。

实现点：

- 使用 Tauri 官方模板初始化。
- 前端保留 `app shell`、路由、状态管理、组件目录。
- 后端按 `svn`、`workspace`、`task`、`staging`、`error` 拆模块。

验收标准：

- 本地能启动开发窗口。
- 前端能调用一个 Rust 测试命令。
- Windows 和 macOS 至少能完成开发模式启动。

### 0.2 前后端通信基础

功能：

- 定义 Tauri command 调用规范。
- 定义统一返回结构。
- 定义错误类型。
- 定义前端 API client。
- 定义后端日志输出。

实现点：

- Rust 错误统一包含 `code`、`message`、`detail`、`recoverable`。
- 前端封装 `invoke`，避免组件直接调用 Tauri。
- 命令错误要能展示给 UI。

验收标准：

- 前端能调用成功命令和失败命令。
- 错误能在 UI 中用统一组件展示。
- 后端日志可在开发终端查看。

### 0.3 应用主布局

功能：

- 搭建工作台主界面。
- 左侧栏：工作区、分支池、仓库、草稿、过滤器占位。
- 中间区域：本地改动、暂存区、日志、分支、仓库浏览占位。
- 右侧区域：Diff、文件详情、属性、锁状态、检查结果占位。
- 底部区域：提交信息、命令输出、任务队列占位。

实现点：

- 使用 CSS grid 或 flex 建立稳定布局。
- 保证窗口缩小时不发生明显重叠。
- 先用占位数据验证信息密度。

验收标准：

- 首屏是工作台，不出现营销页。
- 主区域可以切换基础视图。
- 各面板尺寸稳定，文本不溢出。

### 0.4 任务队列基础

功能：

- 定义后台任务模型。
- 支持任务状态：pending、running、success、failed、cancelled。
- 支持任务日志。
- 支持任务取消占位。
- 前端显示任务队列。

实现点：

- 后端任务需要有 `task_id`。
- 长耗时 SVN 命令后续都必须进入任务队列。
- 前端支持任务列表、详情日志、失败提示。

验收标准：

- 能创建模拟长任务。
- UI 能展示任务进度和日志。
- 失败任务能显示错误信息。

## 阶段 1：基础工作副本和提交闭环

目标：实现打开工作副本、读取状态、查看 diff、文件级暂存、提交已暂存文件、update、revert、cleanup。

### 1.1 SVN 命令行检测

功能：

- 检测 `svn` 是否可用。
- 读取 `svn --version`。
- 显示 SVN 版本和路径。
- 提供手动选择 `svn` 路径的设置入口。

实现点：

- 后端执行 `svn --version --quiet`。
- Windows 需要支持 `svn.exe`。
- 结果写入应用设置。

验收标准：

- 未安装 SVN 时给出明确提示。
- 已安装 SVN 时显示版本。
- 手动配置路径后能重新检测。

### 1.2 打开工作副本

功能：

- 选择本地目录。
- 判断是否是 SVN 工作副本。
- 读取 `svn info --xml`。
- 显示工作副本根目录、仓库 URL、revision、repository root。
- 保存最近打开的工作副本。

实现点：

- 后端解析 `svn info --xml`。
- 非工作副本目录提示 checkout 或重新选择。
- 前端显示当前工作副本摘要。

验收标准：

- 能打开普通 SVN 工作副本。
- 非 SVN 目录有明确提示。
- 重新启动应用后能看到最近工作副本。

### 1.3 工作副本状态扫描

功能：

- 执行 `svn status --xml`。
- 展示 modified、added、deleted、missing、unversioned、conflicted、obstructed。
- 展示文件路径、状态、是否属性变更。
- 支持手动刷新。

实现点：

- Rust 定义 `WorkingCopyStatus`、`ChangedFile`。
- XML 解析失败时展示原始错误。
- 状态列表先不做虚拟滚动，但接口结构要支持分页/过滤扩展。

验收标准：

- 各类基础状态能正确显示。
- 冲突和异常状态有明显标识。
- 刷新后列表与命令行结果一致。

### 1.4 本地改动列表

功能：

- 中间区域展示改动文件。
- 支持按状态分组。
- 支持文件搜索。
- 支持选择当前文件。
- 支持显示统计：总改动、已暂存、未暂存、异常。

实现点：

- 文件行尺寸固定。
- 状态标签颜色清晰但克制。
- 文件路径过长时中间省略。

验收标准：

- 数百个文件时列表仍可用。
- 搜索能即时过滤。
- 点击文件能更新右侧详情。

### 1.5 文件 Diff

功能：

- 对选中文件执行 `svn diff <path>`。
- 显示文本 diff。
- 二进制文件显示不可预览提示。
- 新增、删除文件有对应展示。

实现点：

- 后端提供 `get_file_diff`。
- 前端先用普通文本 diff 组件，Monaco 放到阶段 2。
- Diff 请求需要能处理路径空格。

验收标准：

- modified 文件能显示 diff。
- added/deleted 文件有合理展示。
- binary 文件不崩溃。

### 1.6 文件级虚拟暂存

功能：

- 支持文件级 stage / unstage。
- 已暂存和未暂存分区展示。
- 暂存状态保存在内存中。
- 提交按钮只提交已暂存文件。

实现点：

- 暂存区暂时只记录文件路径和状态。
- 文件状态刷新后要校验暂存路径是否仍存在。
- 异常状态不可暂存。

验收标准：

- 用户可以暂存/取消暂存文件。
- 只提交已暂存文件。
- 冲突、missing、obstructed 默认不可暂存。

### 1.7 提交信息和文件级提交

功能：

- 输入提交信息。
- 显示已暂存摘要。
- 执行 `svn commit <staged paths> -m <message>`。
- 显示提交输出。
- 成功后刷新状态并清空已提交暂存项。

实现点：

- 提交必须进入任务队列。
- 提交信息为空时阻止。
- 提交前检查 staged 文件是否仍然有效。

验收标准：

- 能提交单个文件。
- 能提交多个文件。
- 提交失败时保留暂存状态和提交信息。
- 提交成功后状态刷新正确。

### 1.8 Update、Revert、Cleanup

功能：

- 工作副本级 update。
- 文件级 revert。
- 工作副本 cleanup。
- 显示命令输出。

实现点：

- update 和 cleanup 进入任务队列。
- revert 必须二次确认。
- revert 后刷新状态。

验收标准：

- update 成功后 revision 更新。
- revert 后文件状态恢复。
- cleanup 失败时显示 SVN 原始错误摘要。

## 阶段 2：现代审查和高性能列表

目标：强化 UI、diff、审查、安全检查、搜索过滤和大型列表性能。

### 2.1 Monaco Diff 查看器

功能：

- 集成 Monaco Editor。
- 支持 inline 和 side-by-side 模式。
- 支持语法高亮。
- 支持 whitespace 显示开关。
- 支持只读查看。

实现点：

- 后端需要提供 base 内容和 working 内容，或提供可转换的 diff 数据。
- 大文件需要限制加载大小。
- 二进制文件继续降级展示。

验收标准：

- 常见源码文件 diff 显示清晰。
- inline / side-by-side 能切换。
- 大文件不会卡死 UI。

### 2.2 改动列表虚拟滚动

功能：

- 文件列表使用虚拟滚动。
- 支持数千改动文件。
- 支持固定行高。
- 支持快速滚动和键盘选择。

实现点：

- 列表状态和选择状态解耦。
- 搜索和分组后仍保持虚拟滚动。

验收标准：

- 5000 个改动文件滚动不卡顿。
- 搜索后列表正确更新。
- 选中文件不因滚动丢失。

### 2.3 搜索、过滤和分组

功能：

- 按路径搜索。
- 按状态过滤。
- 按已暂存/未暂存过滤。
- 按异常状态过滤。
- 按目录分组。
- 按文件类型分组。

实现点：

- 过滤状态显示在左侧栏。
- 支持一键清空过滤。
- 统计数量跟随过滤更新。

验收标准：

- 多个过滤条件组合有效。
- 分组折叠/展开稳定。
- 清空过滤后恢复完整列表。

### 2.4 文件审查状态

功能：

- 标记文件已审/未审。
- 按未审过滤。
- 已审状态保存到当前工作副本会话。
- 文件内容变化后自动回到未审。

实现点：

- 审查状态以文件路径和内容摘要关联。
- 暂时保存到本地应用数据。

验收标准：

- 文件可标记已审。
- 刷新状态后已审状态保留。
- 文件变化后已审状态失效。

### 2.5 基础安全检查

功能：

- 检查冲突文件。
- 检查 missing、obstructed。
- 检查 unversioned 文件。
- 检查大型二进制文件。
- 检查日志、临时文件、生成文件。
- 检查 mixed revision。

实现点：

- 检查结果分为阻塞、警告、提示。
- 阻塞项禁止提交。
- 警告项可确认。

验收标准：

- 冲突文件阻止提交。
- 未版本控制文件产生警告。
- 用户确认警告后可以继续提交。

### 2.6 提交信息模板

功能：

- 支持配置提交模板。
- 创建提交时自动填入模板。
- 支持最近提交信息历史。

实现点：

- 模板保存到应用设置。
- 提交历史仅本地保存。

验收标准：

- 新提交能自动带出模板。
- 用户可编辑模板。
- 提交成功后记录历史。

## 阶段 3：持久化虚拟暂存区和部分提交

目标：让暂存区可持久化，并实现文本文件 hunk 级部分提交。

### 3.1 暂存区持久化

功能：

- 保存文件级暂存状态。
- 保存提交信息。
- 保存审查状态。
- 保存已确认警告。
- 应用重启后恢复草稿。

实现点：

- 草稿按工作副本 root 和 repository URL 隔离。
- 保存文件内容摘要。
- 状态刷新后校验草稿是否失效。

验收标准：

- 重启应用后暂存状态恢复。
- 文件变化后对应草稿项标记失效。
- 用户可以清空草稿。

### 3.2 Unified Diff 解析

功能：

- 解析 `svn diff` 输出。
- 得到 file diff、hunk、行变更。
- 标记可部分提交和不可部分提交文件。

实现点：

- 只对文本 modified 文件开放 hunk 选择。
- binary、property-only、rename、conflict 文件不可选择 hunk。
- 解析器需要单元测试覆盖常见 diff。

验收标准：

- 能正确识别多个文件 diff。
- 能正确识别多个 hunk。
- 不支持的文件类型有明确原因。

### 3.3 Hunk 级选择 UI

功能：

- 在 diff 中显示 hunk 选择控件。
- 支持 stage hunk / unstage hunk。
- 显示文件部分暂存状态。
- 已暂存预览只显示选中 hunk。

实现点：

- Hunk id 需要和文件摘要关联。
- 文件刷新后 hunk 选择需要重新校验。

验收标准：

- 用户能选择单个 hunk。
- 同一文件多个 hunk 可分别选择。
- 文件变化后 hunk 选择失效并提示。

### 3.4 Selected Patch 生成

功能：

- 根据选中 hunk 生成 selected patch。
- 支持多文件 patch。
- 支持提交前 patch 预览。

实现点：

- Patch 生成逻辑放在 Rust 后端。
- 生成后需要能被 `svn patch` 应用。
- 单元测试覆盖 hunk 组合。

验收标准：

- 选中 hunk 生成的 patch 内容正确。
- 未选中 hunk 不进入 patch。
- patch 预览和用户选择一致。

### 3.5 影子工作副本管理

功能：

- 创建影子工作副本。
- 按 repository URL 和工作副本 root 缓存。
- 更新影子工作副本到目标 revision。
- 检查影子工作副本状态。
- 支持重建影子工作副本。

实现点：

- 影子副本存放在应用数据目录。
- 不允许用户真实工作区被临时改写。
- 状态异常时提示重建。

验收标准：

- 首次部分提交能创建影子副本。
- 再次部分提交能复用影子副本。
- 影子副本异常可重建。

### 3.6 Hunk 级部分提交

功能：

- 将 selected patch 应用到影子工作副本。
- 在影子工作副本执行提交。
- 提交成功后刷新真实工作副本。
- 提交失败保留草稿。

实现点：

- 执行前检查真实工作副本冲突、mixed revision、文件摘要。
- 影子提交必须进入任务队列。
- 提交后提示用户 update 或执行同步。

验收标准：

- 一个文件多个 hunk 中只提交选中 hunk。
- 多文件选中 hunk 能一起提交。
- 提交失败不影响真实工作副本。
- 不支持场景会阻止并说明原因。

## 阶段 4：仓库浏览、分支池和任务工作区

目标：实现 SVN 分支相关能力，并提供多工作副本分支池。

### 4.1 Repository Browser 基础

功能：

- 输入或从工作副本读取 repository root。
- 执行 `svn list --xml`。
- 浏览目录。
- 显示文件、目录、revision、author、date。

实现点：

- 大目录加载进入任务队列。
- 支持路径面包屑。

验收标准：

- 能浏览 trunk、branches、tags。
- 大目录加载时 UI 不阻塞。
- 错误 URL 有明确提示。

### 4.2 分支和标签识别

功能：

- 自动识别 `/trunk`、`/branches`、`/tags`。
- 展示分支列表。
- 展示标签列表。
- 支持自定义仓库布局。

实现点：

- 默认使用标准布局。
- 非标准布局允许用户手动指定 branches/tags 路径。

验收标准：

- 标准 SVN 仓库能自动识别。
- 非标准仓库能手动配置。

### 4.3 创建分支和标签

功能：

- 从当前工作副本或指定 URL 创建 branch。
- 从当前 revision 或指定 revision 创建 branch。
- 创建 tag。
- 显示创建结果。

实现点：

- 使用 `svn copy`。
- 需要提交信息。
- 创建任务进入任务队列。

验收标准：

- 能从 trunk 创建 branch。
- 能创建 tag。
- 失败时显示 SVN 错误。

### 4.4 分支工作副本池

功能：

- 为分支创建本地工作副本。
- 复用已有工作副本。
- 显示分支 URL、本地路径、revision、本地改动数量。
- 支持快速切换当前工作区。
- 支持清理不再使用的工作副本。

实现点：

- 工作副本池配置保存在应用数据。
- 切换工作区不执行 `svn switch`。
- 每个工作区独立状态缓存和暂存草稿。

验收标准：

- 两个分支工作副本之间切换接近即时。
- 每个分支保留独立本地改动状态。
- 删除池项前必须确认。

### 4.5 任务工作区

功能：

- 创建任务。
- 任务绑定分支工作副本。
- 任务保存暂存草稿、提交信息、审查状态。
- 支持任务列表和快速切换。

实现点：

- 任务是 NovaSVN 层概念，不影响 SVN 元数据。
- 一个分支可以有多个任务，但同一工作副本的改动仍共享文件系统。

验收标准：

- 能创建任务并绑定分支。
- 切换任务后恢复草稿。
- 删除任务不删除工作副本，除非用户明确选择。

### 4.6 svn switch 高级入口

功能：

- 在当前工作副本执行 `svn switch`。
- 执行前检查本地改动。
- 显示风险提示。
- 执行后刷新状态。

实现点：

- 有本地改动时需要二次确认。
- switch 失败时展示冲突或错误原因。

验收标准：

- 干净工作副本能 switch。
- 有本地改动时默认阻止或要求确认。
- switch 后 info 和 status 正确刷新。

## 阶段 5：完整 SVN 协作能力

目标：补齐完整客户端需要的历史、锁、冲突、属性、合并等能力。

### 5.1 Log 和文件历史

功能：

- 显示仓库 log。
- 显示文件历史。
- 显示 revision changed paths。
- 支持按作者、日期、关键字过滤。

实现点：

- 使用 `svn log --xml`。
- 大量日志分页加载。

验收标准：

- 能查看工作副本日志。
- 能查看单文件历史。
- 点击 revision 能查看变更文件。

### 5.2 Revision Diff 和分支比较

功能：

- 比较两个 revision。
- 比较工作副本和 revision。
- 比较两个分支 URL。
- 导出 patch。

实现点：

- 使用 `svn diff` 不同参数组合。
- 大 diff 使用懒加载和降级策略。

验收标准：

- 能查看两个 revision 的差异。
- 能比较 trunk 和 branch。

### 5.3 Lock / Unlock

功能：

- 显示文件锁状态。
- 对文件执行 lock。
- 对文件执行 unlock。
- 支持强制 unlock 入口。

实现点：

验收标准：

- 能锁定文件。
- 能解锁文件。
- 已锁文件提交状态显示正确。

### 5.4 冲突处理基础

功能：

- 显示文本冲突、属性冲突、tree conflict。

- 标记 resolved。
- 提供 mine/theirs 相关入口。

实现点：

- 使用 `svn resolve`。
- 第一版不做完整三方合并器，可调用外部工具。

验收标准：

- 冲突文件明显展示。
- 用户能标记已解决。

### 5.5 Merge 基础流程

功能：

- 从分支合并到当前工作副本。
- 支持选择源 URL。
- 支持选择 revision 范围。
- 支持 dry-run。
- 显示合并结果。

实现点：

- 使用 `svn merge`。
- merge 必须进入任务队列。
- 合并后自动刷新状态。

验收标准：

- dry-run 能显示预计变更。
- 简单分支能合并。
- 冲突合并后进入冲突视图。

### 5.6 SVN Properties 和 Externals

功能：

- 展示文件和目录属性。
- 编辑属性。
- 展示 `svn:externals`。

实现点：

验收标准：

- 能显示 externals 配置。
