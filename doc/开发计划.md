# NovaSVN 开发计划

## 开发原则

NovaSVN 的开发目标是逐步交付一个现代化、高性能、跨平台的完整 SVN 客户端。开发顺序必须先打通稳定闭环，再扩展高级能力。

基本原则：

- `P1` 先保证工作副本打开、状态扫描、diff、暂存、提交这些核心路径稳定。
- `P2` 所有 SVN 操作先通过 `svn` 命令行实现，并统一封装在后端接口中。
- `P3` UI 从第一版开始按完整工作台设计，避免后续大改布局。
- `P4` 大型工作副本性能从第一版就纳入设计，不等后期补救。
- `P5` 虚拟暂存区是核心交互模型，不能依赖临时改写真实工作副本。
- `P6` 部分提交必须通过影子工作副本保护用户真实文件。
- `P7` Windows 和 macOS 都作为目标平台，但系统右键菜单放到后期实现。
- `P8` Git 提交日志必须使用中文。

## 编号规则

本文档中的每一步都使用稳定编号，方便开发、提交、Issue 和验收引用。

- `P*` 表示开发原则。
- `阶段 N` 表示大的开发阶段。
- `N.M` 表示一个可独立开发的功能模块。
- `N.M.F*` 表示该模块的功能项。
- `N.M.I*` 表示该模块的实现点。
- `N.M.A*` 表示该模块的验收标准。

## 阶段 0：工程脚手架和基础架构

目标：建立可持续开发的 Tauri + Svelte + TypeScript + Rust 工程，并定义前后端通信、错误模型、任务模型和基础 UI 框架。

### 0.1 初始化工程

功能：

- `0.1.F1` 创建 Tauri 应用。
- `0.1.F2` 配置 Svelte + TypeScript。
- `0.1.F3` 配置 Rust 后端模块结构。
- `0.1.F4` 配置基础开发脚本。
- `0.1.F5` 配置应用名称、窗口尺寸、图标占位。
- `0.1.F6` 建立 `src-tauri` 和前端目录的约定结构。

实现点：

- `0.1.I1` 使用 Tauri 官方模板初始化。
- `0.1.I2` 前端保留 `app shell`、路由、状态管理、组件目录。
- `0.1.I3` 后端按 `svn`、`workspace`、`task`、`staging`、`error` 拆模块。

验收标准：

- `0.1.A1` 本地能启动开发窗口。
- `0.1.A2` 前端能调用一个 Rust 测试命令。
- `0.1.A3` Windows 和 macOS 至少能完成开发模式启动。

### 0.2 前后端通信基础

功能：

- `0.2.F1` 定义 Tauri command 调用规范。
- `0.2.F2` 定义统一返回结构。
- `0.2.F3` 定义错误类型。
- `0.2.F4` 定义前端 API client。
- `0.2.F5` 定义后端日志输出。

实现点：

- `0.2.I1` Rust 错误统一包含 `code`、`message`、`detail`、`recoverable`。
- `0.2.I2` 前端封装 `invoke`，避免组件直接调用 Tauri。
- `0.2.I3` 命令错误要能展示给 UI。

验收标准：

- `0.2.A1` 前端能调用成功命令和失败命令。
- `0.2.A2` 错误能在 UI 中用统一组件展示。
- `0.2.A3` 后端日志可在开发终端查看。

### 0.3 应用主布局

功能：

- `0.3.F1` 搭建工作台主界面。
- `0.3.F2` 左侧栏：工作区、分支池、仓库、草稿、过滤器占位。
- `0.3.F3` 中间区域：本地改动、暂存区、日志、分支、仓库浏览占位。
- `0.3.F4` 右侧区域：Diff、文件详情、属性、锁状态、检查结果占位。
- `0.3.F5` 底部区域：提交信息、命令输出、任务队列占位。

实现点：

- `0.3.I1` 使用 CSS grid 或 flex 建立稳定布局。
- `0.3.I2` 保证窗口缩小时不发生明显重叠。
- `0.3.I3` 先用占位数据验证信息密度。

验收标准：

- `0.3.A1` 首屏是工作台，不出现营销页。
- `0.3.A2` 主区域可以切换基础视图。
- `0.3.A3` 各面板尺寸稳定，文本不溢出。

### 0.4 任务队列基础

功能：

- `0.4.F1` 定义后台任务模型。
- `0.4.F2` 支持任务状态：pending、running、success、failed、cancelled。
- `0.4.F3` 支持任务日志。
- `0.4.F4` 支持任务取消占位。
- `0.4.F5` 前端显示任务队列。

实现点：

- `0.4.I1` 后端任务需要有 `task_id`。
- `0.4.I2` 长耗时 SVN 命令后续都必须进入任务队列。
- `0.4.I3` 前端支持任务列表、详情日志、失败提示。

验收标准：

- `0.4.A1` 能创建模拟长任务。
- `0.4.A2` UI 能展示任务进度和日志。
- `0.4.A3` 失败任务能显示错误信息。

## 阶段 1：基础工作副本和提交闭环

目标：实现打开工作副本、读取状态、查看 diff、文件级暂存、提交已暂存文件、update、revert、cleanup。

- `1.1.F4` 提供手动选择 `svn` 路径的设置入口。

实现点：

- `1.1.I1` 后端执行 `svn --version --quiet`。
- `1.1.I2` Windows 需要支持 `svn.exe`。
- `1.1.I3` 结果写入应用设置。

验收标准：

- `1.1.A1` 未安装 SVN 时给出明确提示。
- `1.1.A2` 已安装 SVN 时显示版本。
- `1.1.A3` 手动配置路径后能重新检测。

### 1.2 打开工作副本

功能：

- `1.2.F1` 选择本地目录。
- `1.2.F2` 判断是否是 SVN 工作副本。
- `1.2.F3` 读取 `svn info --xml`。
- `1.2.F4` 显示工作副本根目录、仓库 URL、revision、repository root。
- `1.2.F5` 保存最近打开的工作副本。

实现点：

- `1.2.I1` 后端解析 `svn info --xml`。
- `1.2.I2` 非工作副本目录提示 checkout 或重新选择。
- `1.2.I3` 前端显示当前工作副本摘要。

验收标准：

- `1.2.A1` 能打开普通 SVN 工作副本。
- `1.2.A2` 非 SVN 目录有明确提示。
- `1.2.A3` 重新启动应用后能看到最近工作副本。

### 1.3 工作副本状态扫描

功能：

- `1.3.F1` 执行 `svn status --xml`。
- `1.3.F2` 展示 modified、added、deleted、missing、unversioned、conflicted、obstructed。
- `1.3.F3` 展示文件路径、状态、是否属性变更。
- `1.3.F4` 支持手动刷新。

实现点：

- `1.3.I1` Rust 定义 `WorkingCopyStatus`、`ChangedFile`。
- `1.3.I2` XML 解析失败时展示原始错误。
- `1.3.I3` 状态列表先不做虚拟滚动，但接口结构要支持分页/过滤扩展。

验收标准：

- `1.3.A1` 各类基础状态能正确显示。
- `1.3.A2` 冲突和异常状态有明显标识。
- `1.3.A3` 刷新后列表与命令行结果一致。

### 1.4 本地改动列表

功能：

- `1.4.F1` 中间区域展示改动文件。
- `1.4.F2` 支持按状态分组。
- `1.4.F3` 支持文件搜索。
- `1.4.F4` 支持选择当前文件。
- `1.4.F5` 支持显示统计：总改动、已暂存、未暂存、异常。

实现点：

- `1.4.I1` 文件行尺寸固定。
- `1.4.I2` 状态标签颜色清晰但克制。

验收标准：

- `1.4.A1` 数百个文件时列表仍可用。
- `1.4.A2` 搜索能即时过滤。

### 1.5 文件 Diff

功能：

- `1.5.F1` 对选中文件执行 `svn diff <path>`。
- `1.5.F2` 显示文本 diff。
- `1.5.F3` 二进制文件显示不可预览提示。

实现点：

验收标准：

- `1.5.A1` modified 文件能显示 diff。
- `1.5.A2` added/deleted 文件有合理展示。
- `1.5.A3` binary 文件不崩溃。

### 1.6 文件级虚拟暂存

功能：

验收标准：

- `1.6.A1` 用户可以暂存/取消暂存文件。

### 1.7 提交信息和文件级提交

- `1.7.F2` 显示已暂存摘要。

验收标准：

- `1.7.A1` 能提交单个文件。
- `1.7.A2` 能提交多个文件。
- `1.7.A3` 提交失败时保留暂存状态和提交信息。

### 1.8 Update、Revert、Cleanup

功能：

- `1.8.F1` 工作副本级 update。
- `1.8.F2` 文件级 revert。
- `1.8.F3` 工作副本 cleanup。
- `1.8.F4` 显示命令输出。

验收标准：

## 阶段 3：持久化虚拟暂存区和部分提交

- `3.1.F3` 保存审查状态。
- `3.1.F4` 保存已确认警告。
- `3.1.F5` 应用重启后恢复草稿。

实现点：

- `3.1.I1` 草稿按工作副本 root 和 repository URL 隔离。
- `3.1.I2` 保存文件内容摘要。
- `3.1.I3` 状态刷新后校验草稿是否失效。

验收标准：

### 3.2 Unified Diff 解析

功能：
