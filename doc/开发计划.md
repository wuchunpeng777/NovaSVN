# NovaSVN 开发计划

## 执行规则

- 界面和交互以 Versions 的 Working Copy、Timeline、Repository 三个主视图为基线。
- SVN 操作必须走真实后端命令，并在完成后用状态扫描验证结果。
- 不提供 Git 式暂存区；文件勾选仅表示当前提交目标，不持久化。
- 每完成一个可独立验收的小功能，立即运行针对性测试并提交 Git。
- 发现现有实现与目标冲突时允许替换，不为兼容旧设计保留错误模型。

- [x] 未版本控制文件 Add，包含嵌套父目录。
- [x] 版本控制文件和目录 Delete，包含目标归属校验和破坏性确认。
- [x] 工作副本文件和目录 Move、Copy，以及按父目录作用域管理 Ignore。
- [x] Diff、Hunk Patch 生成和影子工作副本部分提交。
- [x] 外部 Patch 原生选择、预检、确认应用和结果统计。
- [x] Log、Revision Diff、Merge、Lock/Unlock、Resolve 和 Properties。
- [x] 仓库目录读取、分支/标签 Copy、Checkout 和 Switch。

- [ ] 工作副本界面尚未达到 Versions 的结构和视觉密度。
- [ ] Repository 文件操作和历史 revision 浏览不完整。

- [ ] 远端认证、证书、非交互和超时策略未统一。
- [ ] 当前主界面组件覆盖仍有限，端到端测试环境尚未完整配置。

## 阶段 5：Patch 与 Merge

### 5.1 Apply Patch

- [x] 使用原生文件选择器选择 `.patch` 或 `.diff`。
- [x] 校验 Patch 文件、目标路径、`.svn` 管理目录和符号链接边界。
- [x] 使用 `svn patch --dry-run` 预检并展示原始输出。
- [x] 使用 SHA-256 绑定用户确认的 Patch 快照，真实应用前对同一快照再次 dry-run。
- [x] 仅在预检无拒绝、跳过和冲突时允许用户确认执行 `svn patch`。
- [x] 展示 applied、rejected、skipped 和冲突结果，完成后刷新工作副本。
- [x] 使用真实临时仓库覆盖中文路径、成功应用、拒绝预检和快照不可变。
- [ ] 增加偏移应用场景，并为极端大输出统一截断任务日志和 IPC 预览。

### 5.2 Merge

- [ ] 支持单源 URL 和 revision 范围。
- [ ] 支持 dry-run 与结果预览。
- [ ] 支持 merge tracking 常用参数。
- [ ] 执行前重新检查工作副本，不依赖旧状态。
- [ ] 冲突结果直接进入 Resolve 工作流。

## 完成标准

只有在以下条件同时满足时，才可声明整体目标完成：

1. Working Copy、Timeline、Repository 三个主视图与 Versions 的信息结构和主要交互一致。
2. Update、Revert、Cleanup、Commit、Merge、Patch、Log、Blame 以及 Add/Delete/Move/Copy 均有真实命令闭环。
3. 常用远端认证和错误恢复可用。
4. Windows 与 macOS 安装包和系统集成通过验证。
5. 自动化测试覆盖主要前后端路径，当前质量门禁全部通过。
