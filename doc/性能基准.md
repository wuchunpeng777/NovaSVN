# NovaSVN 性能基准

## 验收规模

- 50000 个版本控制文件。
- 5000 个本地改动，状态接口按 500 条分页。
- 文件树扫描全部 50000 个文件，只返回前 5000 个节点并明确标记截断。
- 独立文本文件提供 5000 行 Blame。
- 独立文本文件提供 200 条 Timeline 历史。

文件树、工作副本 Blame 和仓库 Blame 使用固定行高虚拟渲染。组件门禁会构造 5000 行输入，断言 DOM 只包含视口和 overscan 范围，并验证最后一行可通过滚动访问。

## 运行入口

首次生成正式数据集并运行：

```bash
npm run benchmark:svn:reset
```

复用已有数据集再次运行：

```bash
npm run benchmark:svn
```

开发期间可先使用 2000 文件、600 改动和 20 条历史的快速数据集：

```bash
npm run benchmark:svn:quick -- --reset
```

Windows 也可以直接运行 PowerShell 薄封装；它调用同一个 Rust 基准，不维护第二套测量逻辑：

```powershell
.\scripts\benchmark-svn-workspace.ps1 -Reset
```

数据集参数变化后必须传入 `--reset`，避免旧工作副本污染结果。每次测量前都会执行 `svn revert -R`，再重新生成固定数量的本地改动。

## 生产路径

基准不是裸 SVN 命令计时，而是直接调用 NovaSVN 的生产函数：

| 步骤 | 生产函数 | 默认阈值 |
| --- | --- | ---: |
| 状态首屏分页 | `scan_workspace_status(offset=0, limit=500)` | 30000 ms |
| 状态末页分页 | `scan_workspace_status(offset=4500, limit=500)` | 30000 ms |
| 文件树扫描与截断 | `list_workspace_files(max_files=5000)` | 60000 ms |
| 单文件 Diff | `get_file_diff` | 10000 ms |
| 5000 行 Blame | `get_svn_blame(max_lines=5000)` | 15000 ms |
| Timeline 历史分页 | `get_svn_log(limit=200)` | 15000 ms |

单项超过阈值会在报告中标记为超时，所有步骤完成后进程以非零状态退出。数量、分页范围、截断状态或返回类型不符合数据集时会立即失败。

## 报告

结果文件不提交 Git，保存在：

```text
.benchmark/svn-large/benchmark-results.json
.benchmark/svn-large/benchmark-results.md
```

JSON 用于机器比较，Markdown 包含平台、SVN 版本、数据规模、各步骤耗时、阈值、结果和 UI 非冻结门禁说明。

## 2026-07-15 macOS 基线

环境：macOS aarch64、SVN 1.14.5。首次 `--reset` 需要为 50000 个路径建立 SVN 工作副本元数据，耗时明显长于后续复用数据集的回归运行。

| 路径 | 实测耗时 | 阈值 |
| --- | ---: | ---: |
| 状态首屏分页 | 1079 ms | 30000 ms |
| 状态末页分页 | 925 ms | 30000 ms |
| 文件树扫描与截断 | 8243 ms | 60000 ms |
| 单文件 Diff | 63 ms | 10000 ms |
| 5000 行 Blame | 130 ms | 15000 ms |
| Timeline 历史分页 | 475 ms | 15000 ms |

总测量耗时 10915 ms，六项全部通过。文件树返回 5000/50000 个节点并明确标记截断；状态末页返回 offset 4500 的最后 500 个改动。

真实 SVN 回归还覆盖稀疏工作副本：根目录使用 `--depth immediates`，单个子目录再提升到 `infinity`。文件树保留未展开的空版本化目录，只读取已展开文件，不虚构仓库中尚未检出的子路径。
