# Release: 1.7 提交信息和文件级提交

## Release Log

### 2026-07-02 提交信息和文件级提交

#### 背景

`1.6 文件级虚拟暂存` 已经支持在前端内存中维护 staged 文件集合。为了形成阶段 1 的基础提交闭环，需要让底部提交区接收提交信息，并将已暂存文件交给后端任务队列执行真实 `svn commit`。

#### 改动

- 后端任务队列从单一模拟任务扩展为任务 payload 模型，保留模拟任务并新增 SVN commit 任务。
- 新增 `create_commit_task` Tauri command，后端执行 `svn commit <staged paths> -m <message>` 并把 stdout/stderr 写入任务日志。
- 前端 API 和类型增加 `CreateCommitTaskRequest`。
- `workspaceStore` 增加提交信息、提交错误、提交任务追踪、提交前 staged 校验和成功后清理能力。
- 底部提交区增加提交信息输入框、校验提示和真实提交按钮。
- App 层接线提交任务创建、任务成功后的状态刷新、暂存清理和提交信息清空。

#### 影响

用户可以对一个或多个已暂存文件执行真实 SVN 提交。提交任务进入底部任务队列，命令输出显示在“命令输出”面板中。提交成功后刷新工作副本状态并清空已提交 staged 文件和提交信息；提交失败时保留 staged 文件和提交信息，方便修正后重试。

#### 风险

本阶段仍不支持 hunk 级提交、提交信息模板、提交历史或提交草稿持久化。任务队列当前仍是内存队列，应用重启后任务记录不会保留；运行中的提交任务暂不支持强制终止底层 SVN 进程。
