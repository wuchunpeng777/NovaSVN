# Release: 0.2 前后端通信基础

## Release Log

### 2026-07-01 建立前后端通信基础

#### 背景

`0.1 初始化工程` 已经提供 Tauri + Svelte + TypeScript + Rust 工程骨架，但前后端调用仍是临时形态：Tauri command 直接返回字符串，Rust 错误未形成前端可消费结构，组件直接调用 `invoke`，UI 也没有统一错误展示能力。后续 SVN 命令、工作副本扫描和任务队列都需要稳定的通信规范。

#### 改动

- Rust 侧新增统一命令响应 `CommandResponse<T>` 和 `CommandResult<T>`。
- Rust 侧扩展 `NovaError`，统一包含 `code`、`message`、`detail`、`recoverable`。
- `ping` 命令改为返回结构化健康检查数据。
- 新增 `fail_for_preview` 开发命令，用于验证失败命令和错误展示链路。
- 前端新增 `CommandResponse`、`CommandError`、`HealthPayload` 类型。
- 前端 `callBackend` 封装 Tauri `invoke`，组件不再直接调用 Tauri API。
- 新增 `ErrorNotice.svelte`，用于统一展示命令错误。
- 主界面增加“连接后端”和“验证错误”入口。
- 后端命令使用开发终端日志输出，便于本阶段验证调用链路。

#### 影响

后续所有前端调用后端命令应通过 `callBackend` 进入统一调用链。后续 SVN 业务错误、任务错误和认证错误都可以沿用当前错误结构扩展，不需要每个组件单独处理 `invoke` 异常。

#### 风险

- 当前错误展示仍是基础组件，后续接入真实 SVN 命令后需要补充更细的错误分类和操作建议。
- `fail_for_preview` 是开发验证命令，后续正式发布前应移除或隐藏。
- 目前只验证了 macOS 开发环境；Windows 仍需在后续环境中验证。
