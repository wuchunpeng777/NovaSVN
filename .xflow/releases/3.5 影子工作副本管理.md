# Release: 3.5 影子工作副本管理

## Release Log

### 2026-07-02 实现影子工作副本管理

#### 背景

开发计划 3.5 要求创建和缓存影子工作副本，支持更新、状态检查和重建，为 hunk 级部分提交保护真实工作副本做准备。

#### 改动

- 新增 `shadow` Rust 模块，按 working copy root 和 repository URL 生成影子工作副本缓存路径。
- 影子工作副本存放在应用数据目录 `shadow-workspaces` 下。
- 新增 `get_shadow_workspace_status` command，可检查影子工作副本是否存在、是否有效和当前 revision。
- 任务队列新增影子工作副本任务，支持 create_or_update 和 rebuild。
- create_or_update 会在不存在时执行 `svn checkout`，存在时执行 `svn update`；rebuild 会先删除旧影子副本再 checkout。
- 右侧详情面板新增影子工作副本状态区，提供检查、准备和重建入口。

#### 影响

- 首次部分提交前可以创建影子工作副本，后续可以复用并更新缓存。
- 影子工作副本操作进入现有任务队列，不会阻塞前端工作台。
- 用户真实工作副本不会被影子流程改写。

#### 风险

- 当前影子副本 checkout 使用工作副本当前 repository URL，复杂分支布局或 peg revision 场景后续仍需增强。
- 当前尚未应用 selected patch 或执行影子提交，这些在 3.6 完成。
