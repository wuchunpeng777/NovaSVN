# Release: 4.5 任务工作区

## Release Log

### 2026-07-02 实现任务工作区

#### 背景

4.4 已实现分支工作副本池。为了支持同一分支工作副本上的多个逻辑任务，需要在 NovaSVN 层保存任务、绑定分支池项并恢复各自草稿，而不影响 SVN 元数据。

#### 改动

- 后端新增 `task_workspace` 模块，将任务工作区配置保存到应用数据目录 `task-workspaces.json`。
- 新增读取、保存和删除任务工作区的 Tauri command。
- 前端新增任务工作区 API 类型、API client 方法和 taskWorkspaceStore。
- 工作区 store 新增导出/导入任务草稿能力，覆盖暂存文件、选中 Hunk、审查状态和提交信息。
- 草稿视图新增任务工作区面板，支持创建任务、绑定分支工作副本、快速切换和删除任务。
- 切换任务时会保存当前任务草稿，打开目标工作副本，并恢复目标任务草稿。
- 删除任务只删除 NovaSVN 任务配置和本地任务草稿，不删除真实工作副本目录。
- 重新运行前端构建、Rust check 和 Rust 单元测试。

#### 影响

用户可以在分支工作副本上创建多个 NovaSVN 任务工作区，并在任务之间恢复各自草稿。该功能不写入 SVN 元数据，不改变现有提交、暂存或工作副本切换方式。

#### 风险

任务草稿当前保存在浏览器 localStorage，跨设备和清理浏览器数据后不会保留。一个分支多个任务仍共享同一真实工作副本文件系统，文件内容改动不会因任务切换自动隔离。
