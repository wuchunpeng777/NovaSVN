# Release: 3.1 暂存区持久化

## Release Log

### 2026-07-02 实现暂存区持久化

#### 背景

开发计划 3.1 要求将文件级暂存、提交信息、审查状态和已确认警告保存为按工作副本隔离的本地草稿，并在应用重启后恢复。

#### 改动

- 新增 workspace draft 本地结构，按 working copy root 和 repository URL 生成隔离存储 key。
- 草稿保存 stagedFiles、commitMessage、reviewedFiles、confirmedWarningIds 和更新时间。
- 打开或恢复工作副本时加载草稿，并在状态刷新后按文件内容摘要校验暂存和审查状态。
- 暂存、取消暂存、编辑提交信息、标记审查、确认警告和提交成功后都会同步草稿。
- 底部提交区新增清空草稿入口，可清除当前工作副本草稿并重置 UI 状态。
- 保留旧已审状态 key 的读取迁移，避免已有本地已审记录直接丢失。

#### 影响

- 应用重启后可以恢复当前工作副本的文件级暂存、提交信息、审查状态和警告确认。
- 文件内容或状态变化后，失效的暂存/审查/警告确认会在刷新状态时被清理。

#### 风险

- 草稿当前仍使用 localStorage，本机存储被清理会导致草稿丢失。
- 草稿只覆盖文件级暂存；hunk 级选择和部分提交将在后续 3.2+ 模块实现。
