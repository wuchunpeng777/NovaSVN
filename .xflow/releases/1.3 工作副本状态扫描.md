# Release: 1.3 工作副本状态扫描

## Release Log

### 2026-07-02 实现工作副本状态扫描

#### 背景

`1.2 打开工作副本` 已经能打开 SVN 工作副本并展示摘要。后续本地改动列表、diff、暂存和提交都需要先读取工作副本的本地状态。

#### 改动

- 扩展 `src-tauri/src/workspace.rs`，新增 `WorkingCopyStatus`、`ChangedFile` 和状态扫描请求/响应。
- 新增 `scan_workspace_status` Tauri command。
- 后端执行 `svn status --xml <working_copy_root>` 并解析 modified、added、deleted、missing、unversioned、conflicted、obstructed 等基础状态。
- 返回文件路径、状态、属性变更状态、异常标识和统计数量。
- 状态扫描接口包含 offset/limit 字段，为后续分页、过滤和虚拟滚动保留扩展点。
- 前端补齐状态扫描类型和 API client 方法。
- `workspaceStore` 保存状态扫描结果、加载状态和错误。
- 主工作区展示总改动、未版本控制、异常统计，并展示基础文件状态列表。
- 工作副本面板新增“刷新状态”入口，打开工作副本后自动扫描一次。

#### 影响

NovaSVN 现在可以读取并展示工作副本本地改动状态，为 `1.4 本地改动列表`、`1.5 文件 Diff` 和后续提交闭环提供数据基础。

#### 风险

- 本阶段没有实现搜索、过滤、分组和虚拟滚动，大型工作副本只返回前 500 项。
- 状态扫描暂不进入任务队列，后续大型工作副本性能优化时需要任务化或增量化。
- 冲突状态展示为基础异常标识，完整冲突处理后续实现。
