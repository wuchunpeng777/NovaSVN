# Release: 2.4 文件审查状态

## Release Log

### 2026-07-02 实现文件审查状态

#### 背景

开发计划 2.4 要求在改动审查流程中支持文件级已审/未审状态，允许用户过滤未审文件，并在文件内容变化后自动让已审状态失效。

#### 改动

- 后端状态扫描为每个改动文件返回 `content_digest`，摘要基于文件内容和 SVN 状态生成。
- 前端工作副本状态新增 `reviewedFiles` 和 `unreviewedOnly`，已审记录按工作副本 root 与 repository URL 隔离保存到 localStorage。
- 状态刷新时会按路径和内容摘要校验已审记录，文件变化、状态变化或文件消失都会让记录失效。
- 左侧过滤器、主列表指标和工具栏增加未审过滤；文件行显示已审/未审徽标。
- 右侧文件详情增加标为已审/标为未审操作，并展示当前审查状态。
- 修正占位 `icon.png` 为 8-bit RGBA，满足 Tauri 生成上下文要求。

#### 影响

- 用户可以在当前工作副本会话中标记文件已审，刷新状态后只要文件内容摘要不变就会保留。
- 用户可以快速筛选仍未审查的改动文件，适配后续安全检查和提交前审查流程。
- 状态扫描会读取改动文件计算轻量摘要，大型工作副本后续仍需要结合分页和性能策略继续优化。

#### 风险

- 审查状态当前使用 localStorage，不是阶段 3 的完整草稿持久化模型；浏览器存储被清理后记录会丢失。
- 内容摘要使用本地文件当前内容，对缺失、目录或无法读取文件使用元数据摘要，极端场景下只提供失效判断的保守近似。
